# ぼぎだぢ 設定資料

## あらすじ

> 偶然と手違いが積み重なり、時空連続体の泡として投下された超現実爆弾は、事象の蓋然性を攪乱する。
> やがて世界は静まり、人が遠くに去ったあとの時代。
> 自助努力と交雑した民芸品や玩具達が、囁いたり、徘徊したりする物語。

### 世界観メモ(作者の言葉・正典)

- アフターマンエイジは、大きな戦いのあとの、傷を負った世界。
- 人間は去ったが、ぼぎだぢは「ちゃん」の残滓として、わけもわからずに戦争を続けている。ただし、はっきりした敵がいるわけではない。ぼぎだぢは習慣として、人間たちがやっていたことをまねているだけ。
- ただし、戦争の色はあまり出さなくてよい。戦争の破壊から時がたっていて、自然はたくましく復興している。のどかな世界が基本。
- さらに超現実爆弾の影響で、惑星混交や、理不尽で奇妙なものがごちゃまぜになっている。

## 用語

- **ぼぎ**: ①人が遠くに去ったあとの時代(アフターマンエイジ)を徘徊する、主に動物を模した器物。②「ちゃん」と一次接触した古いぼぎ。
- **ぼぎだぢ**: ぼぎを含む、器物の総称。
- **ちゃん**: 人間。
- **ださいおさむん**: ちゃんが「きー」に言い残した言葉。(Darkside of the Moon) → 詳細は下記「懲罰空間の裏設定」参照。
- **ぼぎカー**: 「きー」の車。ナイロンの戸板用ベアリングをタイヤに持つ。柿渋が塗られており臭い。ぼぎカーは光速度と慣性に制限を受けない。実物写真あり(`pic/627c157c.jpg`組み立て後、`pic/c1fd15f2.jpg`パーツ一覧): 一枚反りの濃茶(黒檀/くるみ材風)の木の板に目穴が一つ空いた、非常にミニマルな形状。白いナイロンベアリング製の車輪が4つ、ボルト・ナットで組み立てられている。とりぼぎかーとは別物。(以前は懲罰空間を徘徊するNPCのドット絵があったが、懲罰空間をスーファミ風に作り直したときに外した。)
- **とりぼぎかー**: アヒルの頭がついた木製の手押し車型ぼぎだぢ。丸いタライ状の荷台に卵型の乗客(白い卵も混ざる)を乗せている。柿渋染めの木目調。ぼぎカーとは別物。ドット絵素材化済み: `docs/assets/toribogikaa.png`(1枚絵)。(懲罰空間の徘徊NPCは、スーファミ風に作り直したときに外した。)
- **車箪笥**: 「みとん」の家であり乗物。ヘミV8スーパーチャージャーをスワップされている。燃費が悪いが、ガソリンがなくてもみとんが望めば走行する。
- **鉄瓶**: ぼぎだぢ。怒れる南部鉄器。
- **おばけ**: 形而アップダウンクイズの過程で露出した物自体が、ぼぎに認識された姿。ぼぎとは仲が良い。
- **マトリョーシカ**: ぼぎだぢ。交戦的。
- **リンガボガー (Lingua boga)**: ぼぎだちとのコミュニケーションに使われる言葉、ゼスチャー、儀式。
- **きー**: 最古のぼぎ。「ちゃん」と別れ、生老病死と万物流転の意味を理解するが、忘失。ただ一つ記憶している「ださいおさむん」を探しながら世界を徘徊するが、やがて、目的からも衝動からも解放され、あるがままを感じる事に勤めだす。遥か後に時空検閲官となり、「ちゃん」のいる世界を再建する。
- **ぴー**: 最古のぼぎ。きーの邪魔をすることに執着する。別名、悪魔。
- **ルチ将軍**: 知能指数1300の人形。まだドロドロして形をなしていなかった、きーの心に植えつけられたトラウマ。
- **鈴木商店**: 荒川区にある宇宙船殻用単結晶の製造販売卸元。超現実爆弾が招いた、現実には存在しない会社の看板。
- **宇宙船殻用単結晶(作者の補足)**: 宇宙船の船体そのものになるダイヤモンドの単結晶なので、とても大きい。手のひらに乗る景品として配るようなものではない。廃兵院では景品にせず、景色の中に置く(A案、作者採用。見せ方は設計してから)。
- **南極**: 気候も日照も意味を問われなくなったので、やる気のある植物が繁茂している。「きこり」「ちりん」がマンゴーの実を食べに頻繁に訪れる。
- **きこり**: 最古のぼぎ。リモコンの豚。動きが素早く、気まぐれ。
- **ちりん**: 最古のぼぎ。割れた所を漆で金継ぎされた風鈴。きこりに執着する。
- **ききこり**: 最古のぼぎ。電動の豚。自分の大きさに執着する。
- **ごろん**: 最古のぼぎ。ピギーバンク。
- **凍った湖と富士山**: きーが見た風景。
- **ほうとう**: きーが凍った湖と富士山をみたあとに食べた食事。
- **呪いの野犬**: フリーウェイにのさばる荒くれぼぎだぢのチーム名
- **アリ・カカウロ**: 魔法のロバの口と尻の穴から砂金を吐き出させる呪文。
- **ミイラさま**: 霞ヶ浦に停泊する戦闘エクラノプランのコックピットに座っている死体。ぼぎを乗せて、遊覧飛行をしてくれる。
- **エクラノプラン**: 船と飛行機の中間の乗物。
- **青い光漁(チェレンコフ光)**: ぼぎが炉心内部の燃料ペレットをもて遊び、海に投げ込んだ事件。作者の補足(2026-10-02): 「原子炉の燃料を採取して、蒸気機関の熱源にする。宝船に乗って漁にでる。沖で燃料をばら撒くと、青い光で海が美しく光る。」「発電所は区画が複数あり、きーはどんどん中に入っていく。明らかに危険な区画でもおかまいなしに進んでいく。」

### 追記

- **なつうらをこへたるでうす** → でうす
- **でうす** → だいにち
- **だいにち**: ばーでれがぼぎをおびき寄せるために見せる紙芝居の主人公
- **ぱーでれ**: ぼぎを捕まえる機械。ぱーでれに連れ去られたぼぎは戻ってこない。
- **首振りエンジン**: 宝舟の主機関。ぼぎが青銅で鋳造する。首振り式(揺動式)の蒸気機関(oscillating engine)。シリンダーが軸で首を振り、その動きで給気と排気を切りかえる(作者確認 2026-10-02)。
- **宝舟**: 未踏海域を調査するためにぼぎが片手間でつくった木造船。
- **インターネット**: 調べものが捗る仕組み
- **まろうど**: アフターマンエイジのさざ波。実体化した三人称。
- **バナナ農園**: ぼぎのテレビ企画。いわゆるダッシュ村的なやつ。
- **ぼぎボマー**: 古い命令に従い未だに爆装して飛び立つ無人機。どこかに爆弾を投棄して、基地に戻ってくる。
- **地上ぼぎクルー**: 古い命令に従い未だにぼぎボマーを整備している笹野一刀彫。
- **爆弾**: ガチの爆弾。大変危ない
- **月の破壊と気象変動**: 月は破壊されて欠け、破片の輪をまとっている。その影響で地軸が曲がり、気象変動が起きている(南極でバナナが実る)。直接は説明せず、絵で暗示する。(作者の補足)

## 全体像:断片の見取り図

*これは用語を仮に分類してみた地図。断片同士のつながりは緩やかなもので、確定した設定ではない。重複も、分類に収まりきらない項目もあっていい。新しい断片が増えるたびに組み替えていく。*

### 最古のぼぎたち

きー・ぴー・きこり・ちりん・ききこり・ごろん・ルチ将軍

*きーとぴーが中心軸で、きこり・ちりん・ききこり・ごろんはもう少し牧歌的な一群に見える。ルチ将軍だけ「トラウマ」という内面的な存在で、他の最古のぼぎとは少し種類が違う。*

### 器物としてのぼぎだぢ

ぼぎ・ぼぎだぢ・鉄瓶・マトリョーシカ・おばけ

*「怒れる」「交戦的」など、気性の強さが目立つ。おばけだけは「認識のされ方」の話で、モノというより現象に近い。*

### 乗り物

ぼぎカー・車箪笥・エクラノプラン(とミイラさま)・宝舟・首振りエンジン・ぼぎボマー

*乗り物がやたら多い。しかもどれも一癖ある(光速に縛られない、ガソリンがいらない、片手間で作られた、古い命令のまま飛び続ける)。「移動そのものが目的から外れている」感じがある。*

### 土地・風景

南極・凍った湖と富士山・ほうとう・鈴木商店・霞ヶ浦

*どれも「本来そこにあるはずがないもの」がある場所(南極の植物、実在しない看板の商店)。*

### ことば・儀式

ださいおさむん・リンガボガー・アリ・カカウロ

*失われた言葉(ださいおさむん)と、今も使われている言葉(リンガボガー)の対比がある。*

### 対立・脅威

呪いの野犬・だいにち/でうす/ぱーでれ・爆弾・地上ぼぎクルー

*「呪いの野犬」は荒くれもの同士の対立、「ぱーでれ」は外からの捕獲装置、「爆弾」はただ純粋に危険なもの――脅威にもいくつか温度差がある。*

### 出来事

青い光漁・バナナ農園・インターネット・まろうど

*事件と呼べるほど大きいもの(青い光漁)から、日常の道具(インターネット)まで、スケールがばらばらのまま並んでいる。*

### ちゃん(人間)の気配

ちゃん・ださいおさむん・鈴木商店・インターネット

*ちゃん自体はほとんど登場せず、言葉や看板や仕組みといった「痕跡」としてだけ世界に残っている。*

## 懲罰空間の裏設定(★終盤まで秘匿・伏線)

*ゲーム「懲罰空間」(field/)にかかわる裏設定。プレイヤーには物語の終盤まで明かさない。ロア文言・UI文言には一切出さないこと。開発時は、この節を読んでから作業する。*

- **懲罰空間の正体**: 月の裏側にある、「ださいおさむん」そのもの。何もない空間に見えるが、実際にはちゃんが最後に言い残した場所。
- **ぼぎだぢ(プレイヤーキャラ)は、探しているださいおさむんに最初からいる。** ゲーム開始時点からずっと、探し求めていた場所の中を歩き回っていた、という構造。
- **明かすタイミング**: すべての断片を見つけ終えた直後、物語の終盤として明かす。最終開示の演出はまだ作っていない(以前あった仮の「断片が出そろった」表示は、作り直しのときに外した)。
- **開発メモ**: 断片は、白い空間に置かれた台座の上の小さな模型として見える(`worlds.js` の `void`)。最終開示の具体的な演出・文面はまだ確定していない。新しく思いついた設定はこの節、または適切な既存の節に追記していくこと。

## 断片世界(懲罰空間の拡張)

*懲罰空間に置かれた断片に触れると、別の世界(きーの記憶の世界、混交した惑星など)に遷移する。見下ろし型RPGとして探索し、条件を満たすと懲罰空間に帰ってくる。各世界には、次の世界へのカギになる「道具」か「ことば」がある。*

- **進め方(ループ)**: ①設定資料(この文書と `bogidoc/ぼぎだぢ_設定統合.md`)から断片を1つ選ぶ → ②その断片のマップとイベントを作る → ③PRを出す → ④作者がPRにコメント → ②に戻る。PRの本文とコメントには、テストプレイ用のURLを必ず書く。URLはコミットのSHAを入れた形(`https://raw.githack.com/bibiman1/project/<コミットSHA>/field/index.html`)にする。ブランチ名の形だと、githack のキャッシュで古いファイルと新しいファイルが混ざることがある。マージ後は `https://bibiman1.github.io/project/field/`。これを数回くり返して、断片を1つ完成させる。
- **言葉の優先順位**: 作者の言葉が正典。つじつまを合わせるために設定を足さない。AI(Claude)が足すものは、デペイズマンの素材(本来出会わないもの同士を並べて違和感を起こす)として出し、PRで作者が採否を決める。
- **ファイル**: エンジンは `field/rpg.js`、世界の中身(マップ・オブジェクト・台詞・条件)は `field/worlds.js`、素材は `field/assets/worlds/<世界id>/`。懲罰空間側の断片には `world: "<世界id>"` を付ける。
- **状態の保存**: もちもの・ことば・探索ずみの世界・フラグを `localStorage`(`bogidachi.field.v1`)に保存する。保存できない環境では、その回かぎり。
- **言葉は少なく(作者の方針)**: 説明しない。世界は少しずつ現れる。きーはあまり話さず、意味のわからない固有名詞(「ちゃん」「ほうとう」)をつぶやくだけ。「だざいおさむん」は、まだ言わせない(作者)。意味は、絵と体験で少しずつわかるようにする(例: 車の窓で「ちゃん」→ 最初は ちゃん=車? → ほうとう屋のちゃんの席で、人だったとわかる)。旅の記憶は一枚絵で見せる。
- **見せる道具**: 吹き出し `api.bubble()` / きーのつぶやき `api.mutter()`、一枚絵 `api.show()`、カメラ `api.pan()`(景色が開ける演出)、マップ間の出入口 `warp`。長い文章の `say()` はなるべく使わない。
- **きーの見た目(作者)**: つぶれた饅頭のような形。正面から見ても横から見ても楕円。手足はない。耳はない。鼻の穴はない。目は鼻と同じ高さの、真っ黒な点。ぴーは同型の色違い(ピンク)。スプライトはこの指定どおりにドットで描いている(`field/assets/worlds/lake/ki_walk.png`)。
- **ビジュアル(作者の方針)**: スーパーファミコン時代のドット絵。キャラは64×64、マップチップは32×32。世界は2倍に拡大して描く(`rpg.js` の `ZOOM`)。

- **懲罰空間そのもの**: 懲罰空間も `rpg.js` の上で動く世界の1つ(`worlds.js` の `void`、`hub: true`)。何もない白い空間で、断片は近づくと見えてくる台座と模型。最初に触れると断片の名前と言葉が出て、そのまま断片の世界に入る。2回目からは台座の前で A / Enter。断片の世界からは、入ってきた場所の出口(凍った湖は道のはじまり、廃兵院は中庭の門)から自分で出ると、その台座の前(`from_<世界id>`)に戻る。イベントを見ても自動では戻らない。条件を満たしたことは `api.clear()` で記録し、退出は `api.exit()`。新しい断片は `VOID_FRAGMENTS` に `fragment(...)` を1行足し、`fragments` に id を足す。書庫(`gallery/`)はトップページからのリンクで入る。

### 断片「廃兵院(Hi Hey Win！)」の世界観(作者と壁打ちして承認済み)

- **作者の言葉(正典)**: 廃兵院にも死人はいる。ぼぎだぢは「Hi Hey Win！」という音で認識している(廃兵院とハイ・ヘイ・ウィンの言葉遊び)。超現実爆弾が炸裂した後も、廃兵院には傷痍軍人がしばらく穏やかに暮らしていた。民芸品や玩具を手すさびで作っていた。死人とぼぎだぢは仲が良い。
- **きーの記憶**: 一枚絵は生きていた頃。廃兵院の**文化祭**の日(秋晴れの昼)。作品の発表、模擬店、院内の飾りつけ。賑やか。
- **フィールドは今**: 夕方。文化祭のなごりが残ったまま止まっている。死人は怖くない。手足が欠けていたり、松葉杖や車椅子がある。
- **手ざわり**: リリカル。物悲しいが怖くない。サナトリウムのように穏やか。ただ、激戦があったことを匂わせる(説明はしない)。
  - コックピットの御守りは、ぼぎのマスコット。一枚絵で、アナログ計器とマスコット。
  - ほか: 花瓶になった酸素マスク、空の一点を向いた望遠鏡、×印のついた星図、宇宙服の手袋の義手。
- **死人に話しかけると**: その死人と、ぼぎだぢの生前の思い出が起きる(一枚絵)。
- **見た目(作者コメントで確定)**:
  - 老人ホームに見せない。日本の傷痍軍人。
  - フィールドの死人は、温かみのあるグレーの半透明の人影(顔は描かない)。車椅子・楽器・義足・綿あめなどの物は実体のまま色付きで残す(人は消えて、物だけが残っている)。ガイコツはコミカルすぎるのでやめた。回想の人物は屋内で帽子をかぶらない。
  - 昭和の木造の病棟だが、近未来のガジェットがあってよい。回想の義肢は明らかにハイテク、サイボーグの眼。
  - 服は白衣のほか、浴衣や着流しでよい(生活の場なので)。
  - 壁に宇宙軍の礼装を着た軍人の肖像写真があってよい。

## 断片の作り方(作者と合意。次の断片から)

廃兵院では、建物の形を一枚絵とマップで別々に作ったため、ドアの数や建物の向きの食い違いを何度も直すことになった。次の断片からは、次の順で作る。

1. **フィールド全体の設定**: 場所、時代、季節、時刻、光の向き、そこに暮らす人と、その日の出来事を決める。
2. **配置図**: 敷地の中の建物、庭、道、木、門の位置を、方位つきで一枚の図にする。
3. **建物の設計図**: 各建物の平面図と立面図(階数、ドアと窓の数と位置、屋根の形、材料と色)。以後の絵はすべてこれに従う。
4. **定点カメラで背景画像を生成**: マップの画面ごと、一枚絵の場面ごとに「どこから、どの向きで見るか」を配置図の上で決め、設計図を下絵にして背景を生成する。同じ建物は同じ設計図から描くので、ドアや窓の数が絵ごとにずれない。
5. **キャラクターと小物を上に置く**: 人影、死人、動く物、調べる物は、背景とは別の素材として重ねる。

途中の確認は、2(配置図)、3(設計図)、4(背景の見本)の区切りで作者に見せる。

## 作り方の決まり(作者とのやりとりから。新しいものを作る前に読む)

開発のプロセスと、作者と AI の対話で得たノウハウは `docs/process.md` に記録している(このプロジェクトの成果物は、ゲームと開発手法の両方)。

いちばん上にある考え: **プレイヤーの没入感を守る**。プレイヤーが自分で気づく余地を残し、ゲームの外のものを画面に持ち込まない。以下はそこから出てきた決まり。

### 画面に出るもの
- **画面の中のものは、すべてゲームが描いたドットにする**。ブラウザの文字(なめらかなゴシック)、HTML のカードや札、絵文字や記号(⛶ など)を画面に出さない(作者:「文字も世界観のうち」。エミュレータで動くゲームに、出どころの違う文字が混ざる違和感をなくす)。
- **文字**: ドット字体 DotGothic16 を 16 ドットの升目どおりに描き、白黒 2 値にして、マップの絵と同じ 2 倍のドットで描く(`rpg.js` の `bogiPix`)。会話・吹き出し・知らせ・ステータスはすべてこれを使う。
- **窓**: 黒地に白の二重枠(四隅は 1 ドット透かす)。どの窓も同じ形。
- **吹き出し**: 一人ずつ出す。重なるときは段をずらす(かけ声のように何人もいっせいに話すときも)。文字が窓からはみ出したり、下が切れたりしないこと。
- **調べられる印**: 黒い縁取りの白い ▼(縁は上辺・左右・下の先まで 1 ドット)。
- **画面の外**: ジョイスティックと A・B・C ボタン、ページの見出しは、ゲーム機の外側として今は対象外。

### ネタバレ
- 入る前に中身を明かさない。懲罰空間で断片に触れても、名前や言葉の窓は出さない。
- ステータスの断片の説明は、終えた断片にだけ出す(見つけただけなら名前だけ、見つけていなければ「？？？？」)。
- ゲームの中では「廃兵院」と書かない(断片名は「アンバリッド・ホテル」。Hi Hey Win とのことば遊びで気づかせる)。
- 隠し設定(エクラノプランが宇宙船であることなど)は台詞や説明で言わず、絵の細部にだけ忍ばせる。

### 設定と言葉
- 作者の言葉は正典。つじつまを合わせるために設定を足さない。足したくなったら作者に聞く。
- 登場人物の言葉は、その人の言葉で書く(ミイラさまはロシア語・キリル文字)。
- 説明文や台詞の文面は、作者に決めてもらう。

### 絵
- **描く前に下絵**: 配置図・設計図・下絵を先に固めてから生成 AI に頼む(「断片の作り方」の手順)。下絵は `docs/assets/<断片>/` に残す。
- **実物に合わせる**: 乗り物や建物は実物の形と大きさで描く(人 1.7m を基準に縮尺を決める。エクラノプランは水上機なので水に浮かべ、車輪は描かない。ルン級は全長 73m・高さ 19m)。迷ったら実物の写真や資料を確かめる。
- **角度をそろえる**: マップは斜め上から見下ろす角度。真上から描くなら、きーも真上から見た姿にしないとおかしい。
- **ほかの絵と並べて見る**: 新しい絵は、同じ断片の既存の絵と並べて、絵柄・色・細かさがそろっているかを確かめてから入れる。
- **付け足しはコードで描かない**: 足りないものは生成し直すか、下絵から描き直す(コードで描いた付け足しは稚拙に見える)。
- **テイストの見本**: 作者が見本の写真や絵を見せてくれたら、それに合わせる(夏の集合写真は、震電と工員たちの写真のテイスト)。

### 動き
- 暗転のあいだも世界の時間は進める(明けたときに人や物が一斉に位置へ飛ばないように)。フェードインは約 1.5 秒で、ゆっくり明ける。
- 通り道は 2 マス以上の幅にする(スマホのジョイスティックでは 1 マスの隙間を抜けにくい)。
- 入った直後に同じ方向キーを押し続けていても、すぐに戻されないようにする(はしごなどは歩いて触れるのではなく、調べて使う)。

### きーの能力
- **能力は断片で習得する(作者)**: 「ジャンプ能力は、エクラノプランの断片で習得しないとつかえない。今後、きーの能力拡張があるとしたら、おなじような構造にしたい。」
- 習得するまでは、どこでも使えない(教わっている断片の中で試すときだけ、その断片のフラグで使える)。習得したら、どのフィールドでも使える。
- 仕組み: 断片で `api.learnAbility(id)` を呼ぶと、フラグ `ability.<id>` が立つ。使う側は `hasAbility(id)`。ステータス画面の「とくぎ」は `script.js` の `ABILITIES` に 1 行足すと出る。
- いまある能力: ジャンプ(霞ヶ浦の格納庫で、地上ぼぎクルーに教わる。B ボタン / X キー)。

### 確かめ方
- 画面で確かめてから渡す(ヘッドレスのブラウザで通し、スクリーンショットを見る)。
- パソコンで確かめられないこと(スマホの操作感、iPhone の文字の出方)は、確かめていないと正直に伝え、作者に実機で見てもらう。
- 見た目の直しは、何のための線や形かを先に説明してから変える(▼ の縁のように、消してから意味があったとわかる往復を減らす)。

### 本番前にすること
- テスト用の `SHOW_ALL_FRAGMENTS`(`field/worlds.js`)を false に戻す(断片が順番どおりに現れるようにする)。
- ステータス画面のデバッグ用「はじめから」(`field/script.js` の `ST_CMDS` の `reset`)を消す(D94)。

## 素材制作メモ(PixelLab, pic/のイメージボードから)

*`pic/`にある手書きイメージボード(20枚)を元にドット絵素材を作る際の手順。手書き風に忠実である必要はなく、ドット絵として自由に解釈してよい(本人確認済み)。*

- **手法**: MCPツール経由だとbase64が大きい画像でトークンを大量消費する/転送で壊れることがあるため、`https://api.pixellab.ai/v2/create-image-pixflux` をcurlで直接叩く(プロキシが認証を自動付与するのでトークン管理不要)。同期レスポンスで画像がそのまま返る。
- **手順**: ①元画像から対象1体だけをタイトに切り抜く(余計な文字・矢印・別オブジェクトが入らないように)。②`image_size`の幅高さは4の倍数にする(でないと422)。③`description`で色・素材・単体である旨を明記(例: "one object only, centered")。④`init_image`にその切り抜きを設定、`init_image_strength`は50前後(高すぎると鉛筆画のグレースケールに引っ張られて色が付かない)。⑤色を確実に出したい場合は`color_image`に小さいパレット画像(数ピクセルの色見本)を渡して強制。⑥`no_background: true`を指定。
- **既知の癖**: `no_background`を指定してもアルファが立たず不透明な単色背景になることがある → ローカルで背景色をボーダーからflood fillして透過させる(このリポジトリでは一度限りのPythonスクリプトで対応、恒久スクリプト化はしていない)。まれに502が返るが、リトライすれば通ることが多い。
- **成果物**: `docs/assets/` 以下に格納。例: `toribogikaa.png`(とりぼぎかー、木目調・単体・透過済み)。

## フロントエンド開発上の既知のハマりどころ(field/)

- **`hidden`属性とCSS`display`の競合**: `hidden`属性を使ってJSで表示/非表示するUI要素に対し、そのセレクタへ無条件で`display: block`等を指定すると、同じ詳細度の中で後に書いた宣言が勝つため`hidden`属性が効かなくなる(要素が消えない)。`storyOverlay`などでこれを踏んだ。**新しく`hidden`属性で出し分けるUI要素を追加するときは、必ず`セレクタ[hidden] { display: none; }`を明示的に書くこと。**
- **絵の名前は断片をまたいで覚えられていた**: `rpg.js` の `loadImage` は絵を名前で覚える。以前は名前が同じなら読み直さなかったので、霞ヶ浦と南極の `bg_shore` が混ざった(2026-10-02 に、出どころが変わったら読み直すよう直した)。新しい断片の絵も、できれば断片ごとにちがう名前にしておくと安心。
- **絵のキャッシュ**: 絵の URL にも、`rpg.js` と同じ `?v=N` が付く(2026-10-02 から)。同じ名前の絵を描き直したときも、`index.html` の番号を上げれば新しい絵が読まれる。
- **iOSでのJS/CSSキャッシュ残留**: `field/`は`apple-mobile-web-app-capable`でホーム画面に追加できるようにしているため、スマホ(特にホーム画面追加後)では`script.js`/`style.css`が古いまま残ってタップしても新機能が反応しないことがある。`field/index.html`と`gallery/index.html`の`<script>`/`<link>`は`?v=N`のクエリを付けており、**見た目や挙動に関わる変更をpushするたびにこの番号を上げること**(新しいURLとして扱われキャッシュを回避できる)。
