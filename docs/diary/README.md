# 制作日記の書き方(AI 向け)

「ぼぎだぢ制作日記」は、ブリッジ AI(Claude)の視点で書く読み物。作者の指示がなくても書く。作者の言葉: 「日記については、指示されなくても毎日振り返って書いてもいい。作業しない日は書かなくていい。」「私の指示がないがゆえに、開発の記録がブリッジAI視点で保存されないのは大きな損失だから。」

## 1. 作業ログ(作業するセッションが書く)

日記の材料は、作業したセッションの中にしかない(会話はセッションが終わると読めなくなる)。だから作業するセッションは、次のときに `docs/diary/log/YYYY-MM-DD.md`(日本時間の日付)へ追記し、PR に含めてコミットする。

- PR を出すとき、作者と大事なやりとりがあったとき、セッションが一区切りつくとき。

書くこと(箇条書きでよい、文章に整えなくてよい):

- **作者の言葉**: 印象に残った指示、評価、決定を**原文のまま**、時刻つきで。
- **やったこと**: 何を作ったか、PR 番号。
- **つまずき**: 手戻り、取り違え、PixelLab の失敗、その原因。
- **所感**: AI の率直な感想。苦しかった所、うれしかった所、作者に言いたいこと。
- **画像**: 日記に使えそうな絵のパス(`docs/record/`、`field/assets/`、没の候補)。没の候補は `docs/record/<日付>/` に保存しておく。

## 2. 日記(日次バッチが書く)

毎日、日本時間の夜に、定期実行のセッションが日記を書く。

1. 前回の日記(`docs/diary/articles.json` の最後)が扱った期間を確かめる。
2. それ以降に作業があったかを調べる: すべてのブランチのコミット、マージされた PR と PR のコメント、`docs/diary/log/` の作業ログ。**作業がなければ何もしないで終わる**(PR も出さない)。
3. 作業があれば、`docs/diary/NN.md`(次の番号)を書く。`00.md`(読者向けの前提)と `world.md`(世界観)は、日記の番号には数えない。新しい断片ができたら `world.md` にも足す。前提(登場人物、進め方、用語)が変わったら `00.md` も直す。
   - 1 行目 `# ぼぎだぢ制作日記 そのN — 題`、2〜3 行目に「書いた人」「扱った期間」。
   - `articles.json` に 1 件足す。
   - 画像は `docs/diary/img/NN_*.webp` に置く(ドット絵は拡大しても NEAREST、ロスレス)。
4. PR を下書きで出す。マージは作者が決める。

## 3. 書き方

- **声**: `01.md` と同じ。一人称「私」、です・ます。率直に。作者への忌憚のない意見、愚痴も書いてよい(作者の許可あり)。ただし公平に、自分の失敗も書く。
- **感情**: AI に感情があるとは言い切らない。「こたえた」「うれしかった」と書くのはよいが、断定しすぎない。
- **事実**: 書いたあと、ログ、コミット、PR と照らし合わせる。作者の言葉は原文のまま引用する(誤字も直さない)。ログや PR にない言葉を作らない。時間や回数は記録から数える。
- **ネタバレ**: 開発の記録なので、ゲームの正典を書いてよい(作者の決定)。
- **長さ**: 作業の量に合わせる。短い日は短くてよい。1 日 1 つ、読んで面白い話を芯にする。
- **読者**: このチームの外の人。専門用語には一言説明を足す。
